# 检查规范与验收样例

这是配置或生成检查器的共同契约，不要求维护一份跨技术栈的可执行程序。

## 扫描与判定

### 扫描范围与解析

- 扫描整个项目的 Markdown：Git 已跟踪及未忽略的新 `.md` 文件，排除已删除的源文件；无 Git 时扫描项目目录并排除依赖和生成目录。删除目标后仍检查未修改的入链文档。
- 解析标准 Markdown 链接、图片、引用式链接及引用定义中的本地目标；跳过外部 URL。
- 相对路径按源文档目录解析；`/` 开头的 Markdown 路径按仓库根解析。解码 URL 路径，分开处理查询部分和锚点。仓库外目标同样按实际存在性检查。
- `#标题` 检查当前文档，`file.md#标题` 检查目标文档。标题 ID 默认按 GitHub Markdown 规则生成；项目已明确使用其他渲染器时适配并验证其规则。

### Error：确定无效

- 本地目标不存在。
- 路径 URL 编码无效。
- 目标锚点不存在。

### Warning：无法验证

- 权限不足等原因导致无法访问目标。
- 本地目标格式不受支持。
- 锚点无法验证。

报告具体原因，由 agent 结合上下文判断；检查器的支持范围写入项目维护说明。

### Agent 格式与语义审查

反引号路径属于 agent 的格式维护审查，不作为检查器 error。确定性检查器无须穷举语义候选。

### 输出与退出规则

输出源文件、可获得的行列位置、目标和原因，区分 error 与 warning。任一 error 返回非零退出码；仅 warning 不导致失败。工具执行或配置故障也返回失败，并明确报告故障。

## 验收样例

在临时目录构造小型文档仓库，逐项验证实际命令输出和退出状态。现成工具同样验证；项目内实现将这些行为保存为可重复执行的测试。保持样例与真实项目内容隔离。

| 场景 | 预期 |
| --- | --- |
| 存在的普通链接、图片、引用式链接与引用定义 | 通过 |
| 上述形式分别指向缺失文件 | error，非零退出 |
| `docs/guide.md` 引用 `setup.md`，目标为 `docs/setup.md` | 通过；仓库根同名文件不能替代缺失目标 |
| `/docs/setup.md`、带空格的 URL 编码路径、带查询参数的本地链接 | 按约定解析，存在则通过 |
| 非法 URL 编码 | error |
| `../` 指向仓库外已存在／缺失目标 | 分别通过／error |
| 文件存在但访问被拒绝 | warning 无法验证；测试需确认权限拒绝确实发生，特权环境不可声称已验证 |
| 当前文件与跨文件的有效／缺失锚点 | 分别通过／error |
| 中文标题、重复标题、含强调或行内代码的标题 | 与所选渲染器的锚点结果一致 |
| 只有反引号路径或外部 URL | 不产生断链 error |
| 删除被引用目标，入链文档未修改 | error |
| 新增未忽略 Markdown 含断链；忽略的生成目录含断链 | 前者检查；后者排除 |
| 全部通过、仅 warning、存在 error、检查器执行故障 | 依次为零、零、非零、非零退出 |

无法在当前环境覆盖的样例记录为未验证，并说明原因。
