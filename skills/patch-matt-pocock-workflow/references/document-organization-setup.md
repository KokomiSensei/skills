# 文档组织 setup

## 提出可审阅方案

阅读 [文档分类模板](../assets/document-organization.md)，对照项目现有目录、文档用途、README 与 agent 入口，提出采用模板或融合现有结构的方案。已有 `docs/agents/` 等有效分类可保留并映射；按文档用途归类，不仅按文件名或作者判断。

展示以下具体结果供用户审阅：

- 最终目录树、各类用途，以及与现有约定合并的理由。
- 分类说明的落点与拟写内容；推荐 `docs/maintenance/document-organization.md`。
- 待迁移文件的旧路径 → 新路径、需更新的引用和配置；保持原位的文档说明理由。
- README 与 `AGENTS.md` 拟添加的 Markdown 入口链接；AGENTS 入口注明创建、移动或归档文档前读取分类说明。

用户同意后才创建分类说明、迁移文件和添加入口。已有明确批准沿用；调整方案超出批准范围时仅确认新增部分。拒绝或暂缓时保留现状，文档检查器的选择单独继续。

## 落实分类

按获准方案改写模板为项目规范，保留一份权威分类说明。README 提供人类导航入口，`AGENTS.md` 提供条件读取入口；两处链接同一文件，避免重复复制分类表。

迁移获准文件并修正入链、相对路径和引用它们的配置。后续合并 patch 资源时统一使用获准路径；已有同用途文档优先合并，按内容需要创建目录。文档维护说明引用分类说明，检查命令配置在后续文档检查 setup 中完成。

完成条件：分类说明与实际落点一致，两个导航入口可达，获准迁移完整，未批准或未完成事项有明确记录。
