# 共享依赖与项目登记

适用于可跨项目复用且下载成本明显的浏览器二进制、SDK、工具链、模型等。项目依赖清单与锁文件继续管理普通包，不在这里复制整个包清单。

## 查找、复用与下载

1. 从当前项目配置确定版本或 revision、平台与架构要求。读取当前 worktree 的 `.agent-local/dependencies.toml`（若存在），并检查工具原生缓存、安装清单和环境变量。记录是线索，使用前仍验证实际文件存在、版本匹配且能够运行。
2. 已有兼容依赖时直接复用。记录缺失不表示机器未安装；错误路径或环境变量也不意味着需要重新下载。诊断差异后再决定安装。
3. 确认缺少所需版本时，优先通过工具官方安装方式下载到其原生版本化共享缓存。同版本跨项目复用，不同版本并存；不为每个任务在临时目录重复下载，也不强制清除合法的缓存配置。
4. 实际运行最小启动或使用检查后更新登记。安装方法、平台兼容办法和缓存路径记录本机事实，不把某台机器的绕过方式变成通用规则。缺少权限时报告阻塞，不改变执行权限。

共享路径优先使用工具原生发现机制。工具无原生缓存时，先检查已有安装或约定，再选择当前用户缓存下按工具、版本、平台区分的稳定位置，并登记；跨项目均沿用这个发现原则。安装器缺少并发保护时，对同一目标版本使用共享位置上的互斥锁，获锁后重新检查是否已经安装。等待锁超时则报告占用，不删除其他任务的锁或安装目录。复用既有依赖不授权清理其他版本。

## 本地 TOML 登记

每个 worktree 在自己的根目录维护 `.agent-local/dependencies.toml`，通过 Git 本地 exclude 排除，不提交机器路径。多个 worktree 记录独立，实际依赖缓存共享。换机器或分支后重新验证记录。

按实际需要使用 `[[dependencies]]` 记录多项依赖及多个版本。记录字段：`name`、`version` 或 `revision`、`platform`、绝对 `path`、`source`、`install_command`、`verified_by`、`verified_at`。来源和命令必须是实际观察到的；未知字段可省略，不能猜测安装历史。不要记录令牌、凭据或含密钥的下载 URL。

同一 worktree 多 agent 更新时，使用本地登记目录中的互斥锁，持锁后重新读取、按名称/版本/平台合并，保留其他记录；写入同目录临时文件，解析 TOML 验证后原子替换。不要仅凭原子替换就认为避免了并发丢失更新。锁等待有界，超时报告，不强占锁。实际解析器和锁工具按环境选择。

尚未发现依赖时无需创建空登记。验证只证明记录中的环境，不替代项目测试。
