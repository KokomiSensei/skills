# 文档维护

## 文档组织

创建、移动或归档文档时，按用途选择目录。

| 目录 | 用途 |
| --- | --- |
| `docs/agent/` | 给 agent 阅读的行为规范、工作流程和条件读取文档 |
| `docs/findings/by-agents/` | Agent 产出的调研、分析与报告 |
| `docs/findings/TLDR/` | 人类或 agent 编写的精炼版本，链接完整来源 |
| `docs/maintenance/` | 项目的开发与维护文档，包括 dev-spec、命令说明和本文档分类机制 |

按用途而非作者归类：agent 写的维护规范仍放维护目录。报告记录某次分析结果，不能因被引用就自动成为执行规范；需持续约束工作的结论，整理到对应规范文档并链接来源。

## 引用格式

引用实际文档或文件时使用 `[说明](路径)`，便于导航和断链检查。日常编辑时，直接将本次涉及文档中目标明确的反引号文件引用转成 Markdown 链接，保留显示文字；命令、代码示例、变量和占位符按其原用途保留，含义不确定时询问。超出本次文档范围的批量转换，先展示范围并取得一次确认。

## 修改后检查

新增、修改、移动或删除文档后，按下方项目检查入口执行全项目检查或人工核对；配置检查器时修正本次改动引入的 error。对 warning 结合上下文判断，报告未解决问题及存量问题。

## 项目检查入口

> 占位符。安装时按项目实际配置填写本节：实际命令、运行目录、必要安装步骤、支持范围及已批准的自动运行位置。本次暂不配置检查器时保留已有有效入口；项目尚无检查器时，写明这一状态并要求修改后人工核对引用。
