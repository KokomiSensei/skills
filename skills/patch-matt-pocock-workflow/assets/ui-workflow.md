# UI/UX 工作约定

适用于所有 UI/UX 工作，与使用哪套开发工作流无关。

## 设计与实现

1. 阅读 `ui-ux-pro-max` 的相关指导，结合现有界面，明确主要操作、信息层级和默认展示内容。可以复用上下文中已有的完整指导与设计决策；
2. 新布局或明显交互变化，先完成一个代表性状态，查看实际渲染并修正问题，再扩展其他状态。小改动按影响范围验证。
3. 交付前查看受影响状态的实际页面并操作关键流程；涉及响应式布局时覆盖桌面与窄屏。保留截图、视口和复现入口，分别说明功能测试与 UI/UX 验证结果。运行或编写浏览器测试前，阅读[测试约定](writing-tests.md)。

## 委派与审查

- 委派 UI/UX 实施或审查时，附上本文路径、已有设计决策及可用的页面入口和截图。使用 `code-review` 时，将本文列入 Standards sources，由 Standards reviewer 承担 UI/UX 审查。
- 审查者应用 `ui-ux-pro-max` 的相关指导，查看实际渲染；涉及交互变化时实际操作。检查主要操作是否清晰、信息层级与密度是否合理、长内容和反馈是否易用，以及受影响的响应式布局。
- 审查结果单列 UI/UX 结论；问题应指出具体状态或截图、用户影响和修改方向。缺少实际渲染或必要的交互验证时，标记为“尚未验证”，功能测试通过不能代替 UI/UX 审查通过。
