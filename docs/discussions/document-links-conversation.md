## 助手（进度说明）

## 助手

看过了，这个机制适合纳入补丁，而且它提供了实际检查，不只是一条文档约定。

目前 [check-links.ts](/data00/subw/ta-stuff/data-governing/scripts/check-links.ts) 会：

- 扫描 Git 已跟踪和未忽略的新 Markdown 文件。
- 用 Markdown 解析器检查链接、图片及引用定义的本地目标。
- 发现问题时输出文件、行列和原因，并返回失败状态。
- 通过 `lint:docs → lint → CI` 接入检查流程。

它不检查外部网址和标题锚点，也不会检查反引号里的路径。

**有一个需要适配的地方**：它把所有仓库外链接视为错误，而我们的补丁允许引用上级 `AGENTS.md`。直接复制会让这两项规则冲突。

建议新增“文档链接检查”补丁：复用项目已有检查器，没有时再按项目技术栈补齐，并接入 lint/CI；对用户确认的上级 agent 文档引用设置明确例外。

你希望它**实际安装检查机制并接入 lint/CI**，还是只写成指导 agent 后续配置的约定？我建议前者，才能持续发现断链。

## 用户

我想把他拓展为一个独立的文档审查skill，包括断链扫描和文档链可视化。断链扫描包括内置的可运行脚本，和（我还没想好）。文档链可视化是个技能，用户唤醒，agent不可见：让agent扫描项目中从AGENTS.md开始的各种条件跳转文档链，并通过mermaid图画出来，来让用户知道目前项目里的文档如何影响agent行为。然后patch安装的时候在agents.md里添加上对文档维护的建议（即第一个断链扫描那个）

## 助手

可以。这里有两种用途，建议分成两个独立技能，共享同一套扫描能力：

- **`check-doc-links`**：检查文档链接，附带可运行脚本。由个人补丁向项目 `AGENTS.md` 添加维护入口，让 agent 在修改、移动或删除文档后运行检查。
- **`map-agent-docs`**：仅由用户显式调用。从 `AGENTS.md` 出发，沿文档入口追踪“什么条件下读取什么文件”，生成 Mermaid 图。图中的边标注触发条件，节点简述对 agent 行为的影响。

可视化需要 agent 阅读并理解指令，不能仅靠提取 Markdown 链接。例如：

> 修改 UI 前阅读 `ui-workflow.md`

这是有条件的加载关系；文档里作为示例出现的路径则不一定是加载入口。图上也应区分“规定了什么行为”和“本次实际执行了什么”，扫描只能确定前者。

先确认两个设计点：

❓ **Q1 — 是否按上述方式拆成两个技能？**

➡️ **建议：是。** 断链检查可以由 agent 按项目维护规则使用；可视化设为仅用户调用。这样不会因为“agent 不可见”而阻碍自动检查。

❓ **Q2 — 第一版断链扫描包含哪些引用？**

➡️ **建议先覆盖本地 Markdown 链接、图片、引用定义，以及 agent 指令中反引号包裹的文档路径。** 前三种由脚本确定性检查；反引号路径先作为候选，由 agent 判断它是实际引用、示例还是尚未创建的目标，避免把示例路径判成断链。标题锚点和外部网址暂不纳入。

你说的“脚本和还没想好的另一部分”，可以由这层 **agent 对候选引用的语义审查**来承担。

## 助手

这样更直接：

- **断链扫描纳入 `patch-matt-pocock-workflow`**：附带可运行脚本，安装时部署到目标项目，并在 `AGENTS.md` 添加文档维护入口。
- **`visualize-agent-docs` 独立成技能**：仅用户显式调用，从 `AGENTS.md` 追踪条件加载关系，用 Mermaid 展示文档如何影响 agent 行为。

还需要确定扫描的范围和接入方式：

❓ **Q1 — 第一版是否只自动检查明确的本地 Markdown 链接？**

➡️ **建议：是。** 覆盖链接、图片和引用定义；反引号中的文档路径交给 agent 审查。对用户确认添加的上级 `AGENTS.md` 引用设置例外，不一律判为断链。

❓ **Q2 — 安装补丁时是否同时接入项目已有的 lint 和 CI？**

➡️ **建议：是，有现成入口就接入；没有则提供独立运行命令。** 不为了这个检查额外建立整套 CI。`AGENTS.md` 要求修改、移动或删除文档后运行检查。

## 助手

从“引用的文件是否存在”看，两者没有本质区别。区别只在于：Markdown 链接明确表示引用；反引号还可能表示命令、示例或占位符。我之前据此把它们拆成两套检查，确实不必要。

可以统一处理：

- 扫描 Markdown 链接和反引号中可识别的文档路径，检查目标是否存在。
- 对示例、占位符等无法确定的引用单独报告，由 agent 结合上下文判断。
- 上级 `AGENTS.md` 按实际路径检查：存在就通过，不存在就报断链；权限不足则报告无法验证，不需要特殊白名单。

接入方式也改为：**安装补丁时，让用户选择只提供扫描命令，还是接入项目现有的 lint／CI**，agent 根据项目现状给出建议。

## 用户

对于[]()的链接和md里其它形式的链接（比如图片之类的），直接判断是否断链；对于 `docs/../` 这种形式，通过正则表达式识别后也直接判断是否断链。以上断开为error，应该能直接打断ci或者precommit。对于其他形式的断链，报告warning交给agent判断。

## 助手

明确，扫描结果分成两级：

- **Error**：Markdown 链接、图片、引用式链接等明确引用，以及正则识别出的反引号文档路径，解析后目标不存在。出现任一 error，脚本返回非零退出码，可阻断 CI 或 pre-commit。
- **Warning**：其他疑似文档引用或无法明确解析的引用，报告位置和原因，由 agent 判断；不影响退出码。

路径按引用所在文档的位置解析，允许指向仓库外；上级 `AGENTS.md` 同样按是否实际存在判断。无法访问的目标标记为无法验证，不直接判为断链。

补丁安装时展示建议，让用户选择独立运行，或接入现有 lint、CI、pre-commit。
